Key Decision: Component Strategy

The design system ships with tokens.css + utility classes (.btn, .input, .chip, .card). How should we apply this?

A

Map MUI Theme to Tokens

Keep MUI components but override palette/typography/shape to match the design system. Dark mode via MUI's createTheme({ palette: { mode: 'dark' } }). Minimal code churn, but some MUI-specific styling may leak through.

B

CSS Utility Classes + Minimal MUI

Import tokens.css and tokens-dark.css globally. Use custom CSS classes for most components (buttons, inputs, chips, cards). Keep MUI only for complex composite components (Dialog, Select, Tabs). Full visual fidelity, but more manual class management.

C

MUI sx + CSS Variables

Use CSS custom properties for colors/spacing, but apply them through MUI's sx prop everywhere. No external CSS files needed — all styling lives in TSX. Clean dependency story, but verbose and harder to maintain consistency.

Another Decision: Icon Strategy

The design system includes a custom 16px stroke icon set. Current app uses MUI Material Icons.

A

Adopt Custom SVG Icons

Use the inline SVG icons from design_system/icons.jsx. They match the design system's lighter stroke weight and terracotta accent feel exactly.

B

Keep MUI Icons

Map MUI icon colors to the new token palette. Faster to implement, but visual match won't be exact.
