Key Design Questions

A

Promise-based pause at tool handler level

The safe_bash extension returns a Promise that resolves when user approves/rejects. The Pi agent loop naturally awaits tool results — no special sentinel needed. Cleanest fit with existing pattern.

Pros

  • Natural fit — Pi SDK already awaits tool results
  • No special error types or sentinels
  • Agent continues seamlessly after resolution

Cons

  • Blocked commands accumulate open promises
  • Need timeout fallback (e.g. 5 min auto-reject)
B

Event-driven with tool re-invocation

Blocked command fails immediately with a special error. User approval triggers a separate "retry with allowlist" flow. Agent gets told to call safe_bash again.

Pros

  • No long-lived promises
  • Agent explicitly knows it was blocked and re-requests

Cons

  • Agent may not understand to retry
  • Duplicates flow — error + retry vs single await
  • Breaks existing tool return pattern
