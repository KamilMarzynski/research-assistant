Run 11: Data Flow + Blocklist Design

Promise-based pause at tool level; EventBus + IPC bridge; session-scoped allowlist

Data Flow: Blocked Command → Approval → Resume

End-to-End Flow
1. Agent calls safe_bash("curl https://...")
checkBlocklist(command) → matches /\\bcurl\\b/
↓
2. runSafeBash: instead of throwing, create promise + return pending sentinel
- store { command, reason, projectId } in in-memory blocked-queue
- EventBus.emit("bash:blocked", payload)
- return { pending: true, commandId } (sentinel)
↓
3. EventBus → ipc-handlers.ts
eventBus.on("bash:blocked") → win.webContents.send(IPC.BLOCKED_COMMAND, payload)
↓
4. Renderer: PendingCommandBanner + Modal
- Banner appears (like PendingToolBanner)
- User clicks Review → Modal shows: command + reason + buttons
- User clicks Approve/Deny → invoke(IPC.RESOLVE_BLOCKED_COMMAND, { commandId, action })
↓
5. IPC handler resolves blocked promise
- Lookup blocked promise by commandId
- If "approve_once": execute via runSafeBashInternal(command) → resolve promise with result
- If "approve_session": add command hash to session allowlist → execute → resolve
- If "deny": resolve promise with reject(errorWithReason)
↓
6. Agent
- Await resolves → gets stdout/stderr or rejection
- Continues normally

Blocklist Refactor: New Shape

Each blocklist entry gains a human-readable reason + category for the UI and for the agent

interface BlocklistEntry { pattern: RegExp; key: string; // e.g. "recursive_delete" reason: string; // e.g. "Would recursively delete files" category: 'destructive' | 'privilege_escalation' | 'exfiltration' | 'persistence'; } Explanations are returned to: - User in PendingCommandModal - Agent in the rejection error, so it can self-correct

Session Allowlist

Per-session in-memory Set of command hashes. Cleared on app restart. "Approve session" means future exact-match commands pass through without blocking.

IPC Channels Needed

BLOCKED_COMMAND
main → renderer: { command, reason, commandId, timestamp, agentId }
RESOLVE_BLOCKED_COMMAND
renderer → main: { commandId, action: 'approve_once' | 'approve_session' | 'deny' }
GET_AUDIT_LOG
renderer → main: { limit? } → returns Array
