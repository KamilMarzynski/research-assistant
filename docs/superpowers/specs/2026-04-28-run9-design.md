## Section 1: Palette & Typography

### Palette (dark mode, primary mode for this app)

| Token | Value | Use |
|---|---|---|
| `primary.main` | `#5C6BC0` | Intellectual Indigo — buttons, active states, highlights |
| `secondary.main` | `#26C6DA` | Scientific Teal — accents, chips, secondary actions |
| `background.default` | `#0D0F14` | Near-black app background |
| `background.paper` | `#13161E` | Slightly lighter for surfaces (sidebar, modals) |
| `text.primary` | `#E8EAED` | Main text |
| `text.secondary` | `#8A9BB0` | Muted labels, metadata |

### Typography

- **Headlines (h1–h4):** Manrope — installed via `@fontsource/manrope`
- **Body, data, UI (body1, body2, caption, button, subtitle1, subtitle2):** Inter — installed via `@fontsource/inter`
- Fallback chain: `system-ui, -apple-system, sans-serif`

### Changes to `theme.ts`

- `palette.mode: "dark"` explicit
- Full palette object as above
- `typography.fontFamily` set to Inter; `h1–h4` variants override to Manrope
- `shape.borderRadius` stays `12`
- `styleOverrides`:
  - `MuiPaper.root`: `{ backgroundImage: "none", border: "none" }` — removes MUI's default elevation border
  - `MuiCard.root`: `{ border: "none" }`

## Section 2: Glassmorphism & Border Removal

### `src/renderer/styles/glass.ts`

New file. Exports a single `glassSx` constant:

```ts
export const glassSx = {
  background: "rgba(19, 22, 30, 0.6)",
  backdropFilter: "blur(12px)",
  WebkitBackdropFilter: "blur(12px)",
  boxShadow: "0 4px 24px rgba(0,0,0,0.4)",
} as const;
```

### Surfaces that receive `glassSx`

| Component | How applied |
|---|---|
| `SettingsModal` | `Dialog` `PaperProps={{ sx: glassSx }}` |
| `PendingToolModal` | `Dialog` `PaperProps={{ sx: glassSx }}` |
| `ResearchStatusBar` | Spread into container `Box sx` |
| `PendingToolBanner` | Spread into container `Box sx` |

### Border removal

These patterns are removed from components and replaced with background color contrast or spacing:

- `borderTop: 1, borderColor: "divider"` on LeftSidebar header and footer → use `bgcolor: "background.paper"` contrast against sidebar body
- `borderTop: 1, borderColor: "divider"` on ChatPanel API-key warning bar → use background contrast
- Any `borderBottom: 1` on panel containers → removed

**Not removed:** MUI `<Divider>` components inside lists. These stay.

## Section 3: Playwright Setup & Tests

### Installation

```bash
bun add -d @playwright/test playwright
bunx playwright install --with-deps chromium  # Playwright needs Chromium for Electron
```

`playwright.config.ts` at repo root:
- `testDir: "./e2e"`
- `timeout: 30_000`
- No `webServer` block — tests build and launch Electron directly
- Single project: `{ name: "electron" }`

Tests require a production build before running: `bun run build && bun run test:e2e`.

`package.json` gains:
```json
"test:e2e": "playwright test"
```

### Test files in `e2e/`

**`e2e/helpers/electron.ts`** — shared launch helper:
```ts
// launches app, returns { app, page }
// app = ElectronApplication from _electron.launch({ args: ['out/main/index.js'] })
// page = await app.firstWindow()
```

**`e2e/create-project.spec.ts`**

1. Launch app
2. Click "New project" button in sidebar
3. Type project name into text field
4. Press Enter
5. Assert: new project name visible in sidebar list

---

**`e2e/send-message.spec.ts`**

1. Launch app
2. Create a project (reuse create flow)
3. Type a message into `MessageInput`
4. Click send (or press Enter)
5. Assert: user message bubble visible in message list
6. Assert: streaming cursor (`...` or similar) appears while response streams

> Note: this test requires a valid API key in `userData/settings.json`. Test will be skipped (via `test.skip`) if `GET_SETTINGS` returns `hasApiKey: false`.

---

**`e2e/research-result.spec.ts`**

1. Launch app, create project, select it
2. Evaluate JS in renderer to simulate `RESEARCH_STATUS_UPDATE` IPC event:
   ```ts
   await page.evaluate(() => {
     window.electronAPI._simulateEvent('RESEARCH_STATUS_UPDATE', {
       taskId: 'test-task',
       projectId: '...',
       status: 'running',
       query: 'Test query',
       progress: 0.5,
     });
   });
   ```
3. Assert: `ResearchStatusBar` is visible and displays "Test query"

> `window.electronAPI._simulateEvent` is a test-only helper added to the preload that fires registered `on()` listeners — no new IPC channel, no main process involvement.

---

**`e2e/approve-pending-tool.spec.ts`**

1. Launch app, create project, select it
2. Simulate `TOOL_PENDING` IPC event with a mock pending tool payload
3. Assert: `PendingToolBanner` is visible
4. Click banner to open `PendingToolModal`
5. Assert: modal shows tool name and SKILL.md preview
6. Click "Approve"
7. Assert: modal closes; banner disappears

---

### `_simulateEvent` preload helper

The preload (`src/preload/index.ts`) gains one test-only export on `window.electronAPI`:

```ts
_simulateEvent: (channel: string, payload: unknown) => void
```

Only registered when `process.env.PLAYWRIGHT_TEST === '1'` (set by the `test:e2e` script via `cross-env` or inline env prefix). Calls all registered `on()` listeners for that channel directly. No `ipcRenderer.send` involved — purely in-renderer.

This keeps tests honest (real renderer code runs, real components render) while avoiding the need for a live agent.
