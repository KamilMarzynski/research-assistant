# Run 7 — Design Spec
# Memory & Observability

**Date:** 2026-04-24
**Status:** Approved

---

## Goal

Give the main chat agent persistent, project-scoped memory across sessions using Mastra Observational Memory. Add LangFuse proxy-based tracing for all LLM calls. Research and evaluator agents remain ephemeral — no memory engine involved.

---

## Guiding Principles

**One agent, one session per project.** The main chat agent is the single persistent "person" the user always talks to within a project. It accumulates memory across restarts, synthesises knowledge from past sessions, and orchestrates research workers.

**Research agents are ephemeral.** Spawned fresh per task, no Mastra, no memory. They receive only what the orchestrator explicitly passes. Memory access for research agents is explicitly deferred to a future run.

**MemoryManager is the only Mastra surface.** `AgentSession` never imports Mastra directly. All memory interaction goes through `IMemoryManager` — the swap seam is preserved.

**LangFuse is optional infrastructure.** Missing env keys → silent fallback to direct OpenRouter. No crash, no user-visible error.

## 1. MemoryManager Service

### File
`src/main/services/MemoryManager.ts`

### Interface
```ts
export interface IMemoryManager {
  buildContext(projectId: string, maxRecent: number): Promise<{
    summary: string;           // Mastra-compressed memory log (empty string if no history)
    recentMessages: Message[]; // last maxRecent raw turns for Pi replay
  }>;
  save(projectId: string, turns: Array<{ role: 'user' | 'assistant'; content: string }>): Promise<void>;
}
```

### Implementation
`@injectable()` + `@singleton()`. Registered in `bootstrap.ts` under new DI token `MEMORY_MANAGER`.

**Constructor receives:**
- `settingsService: SettingsService` — API key read lazily at compression time (not at construction), handles the case where key is not yet configured at app start
- `dbPath: string` — `app.getPath('userData')/research-assistant.db` (same file as Drizzle, no collision — Mastra uses `mastra_*` prefixed tables)

**Mastra setup:**
```ts
const store = new LibSQLStore({ url: `file:${dbPath}` });
const memory = new Memory({
  storage: store,
  options: {
    lastMessages: 20,            // constructor default; overridden per-call via lastN in recall()
    semanticRecall: false,       // deferred — no vector store in Run 7
  },
  observer: {
    model: getModel("openrouter", COMPRESSION_MODEL),  // direct OpenRouter — see LangFuse note below
    triggerTokenCount: 30_000,
  },
  reflector: {
    model: getModel("openrouter", COMPRESSION_MODEL),
    triggerTokenCount: 60_000,
  },
});
```

**LangFuse gap — Observer/Reflector calls:** Mastra's internal compression LLM calls go directly to OpenRouter and are **not** routed through the LangFuse proxy. They will not appear in LangFuse traces. This is acceptable for Run 7 — compression calls are infrastructure, not user-facing interactions. Flagged for future resolution when dev-config file is introduced.

`COMPRESSION_MODEL` is a module-level constant: `"anthropic/claude-haiku-4-5"`. Not configurable in Run 7 — flagged for dev-config file in a future run.

**`buildContext` implementation:**
- Calls `memory.recall({ resourceId: projectId, threadId: projectId, lastN: maxRecent })` — `lastN` at call time overrides the constructor's `lastMessages` default, giving per-project control
- Returns compressed summary string + raw recent messages array
- Returns `{ summary: '', recentMessages: [] }` on first use (no history yet)

**`save` implementation:**
- Reads `apiKey` lazily from `SettingsService.getSettings()` before each Observer/Reflector compression call — handles app-start state where key is not yet configured
- Calls `memory.saveMessages({ resourceId: projectId, threadId: projectId, messages: turns })`
- Mastra internally checks token thresholds and fires Observer/Reflector as needed (async, non-blocking)
- If no API key configured: `save` still persists messages to storage; Observer/Reflector silently skip (no LLM call without a key)

### DI token
```ts
// src/main/di/tokens.ts addition
export const MEMORY_MANAGER = Symbol('MEMORY_MANAGER');
```

## 2. AgentSession Changes

### New options
```ts
export interface AgentSessionOptions {
  // ... existing fields ...
  memoryManager: IMemoryManager;
  maxRecentMessages: number;   // from project row, default 20
  langfuseEnabled: boolean;    // from settings
}
```

### Session startup flow

```
buildContext(projectId, maxRecentMessages)
  → { summary, recentMessages }

systemPrompt = [
  isFirstRun ? FIRST_RUN_PROMPT : BASE_SYSTEM_PROMPT,
  summary,       // injected if non-empty
  systemContext, // skills, config.md, AGENTS.md (existing)
].filter(Boolean).join('\n\n')

model = createModel(model, apiKey, langfuseEnabled)

new Agent({
  initialState: {
    systemPrompt,
    model,
    messages: recentMessages,  // Pi conversation history replay
  },
  ...
})
```

**Implementation note:** verify `initialState.messages` is supported in `@mariozechner/pi-agent-core`. If not: format `recentMessages` as a `<conversation_history>` block appended to `systemPrompt` as fallback. Check Pi SDK source at implementation time.

### agent_end handler addition
```ts
} else if (e.type === "agent_end") {
  if (this.assistantContent) {
    await this.messageService.addMessage(...);  // existing — UI persistence
    await this.memoryManager.save(this.projectId, [
      { role: 'user', content: this.lastUserContent },
      { role: 'assistant', content: this.assistantContent },
    ]);                                         // new — Mastra memory
    this.assistantContent = "";
    this.lastUserContent = "";
  }
  this.win.webContents.send(IPC.MESSAGE_DONE);
}
```

`lastUserContent` captured in `send()` before `agent.prompt()`.

### Research agents — explicit exclusion

`ResearchService.startResearch()` spawns Pi `Agent` directly. No `IMemoryManager` parameter. No `buildContext` call. No Mastra imports anywhere in `ResearchService` or its workers. Enforced structurally — not by convention.

## 3. LangFuse Proxy Integration

### Model factory
**New file:** `src/main/agent/model-factory.ts`

```ts
export function createModel(model: string, apiKey: string, langfuseEnabled: boolean): PiModel
```

**Logic:**
- If `langfuseEnabled` AND all three env vars present (`LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_HOST`):
  - Return Pi model configured with LangFuse proxy as `baseURL`, LangFuse credentials in auth header, `x-target-url: https://openrouter.ai/api/v1` forwarded to OpenRouter
  - Session tagged: `{ sessionId: projectId, userId: "local" }` in request metadata
- Otherwise:
  - Return `getModel("openrouter", model)` — existing behaviour, no change

**Implementation note:** verify whether `@mariozechner/pi-ai`'s `getModel` accepts custom `baseURL` + headers, or if a raw OpenAI SDK client must be constructed and passed to Pi. Resolve at implementation time.

**Fallback behaviour:** if LangFuse keys are absent, `createModel` logs a warning to console and returns the direct OpenRouter model. No throw, no user-visible error.

### Environment variables
`.env` file (gitignored, developer only, not shipped):
```
LANGFUSE_PUBLIC_KEY=pk-...
LANGFUSE_SECRET_KEY=sk-...
LANGFUSE_HOST=https://cloud.langfuse.com
```

Loaded in main process via Node.js `process.env` — NOT via `import.meta.env` / renderer. `electron-vite` config exposes them to the main process entry only.

**Future:** these will move to a user-distributable dev-config mechanism (not scoped to Run 7).

### Settings change
```ts
interface Settings {
  apiKey: string;
  model: string;
  langfuseEnabled: boolean;  // new, default false
}
```

`SettingsService.getSettings()` returns `langfuseEnabled: false` as default if absent from `settings.json`. `saveSettings()` persists it. `SettingsModal` gains a simple toggle switch labelled "LangFuse tracing".

## 7. Future Items (Out of Scope for Run 7)

- **Dev-config file**: hardcoded defaults (compression model, LangFuse host) extracted into a distributable config mechanism. Flagged for a dedicated config run before distribution.
- **User-distributable LangFuse**: users who build from source can set their own LangFuse credentials. Will move from `.env` to a runtime config approach (option B from brainstorm).
- **Research agent memory**: ephemeral research agents receiving read-only project memory snapshot for context. Deferred to a future run.
- **`maxRecentMessages` UI**: per-project settings panel. Run 9.
- **Semantic recall**: Mastra vector store + embedder for `semanticRecall: true`. Not in scope until use cases are clear.
- **Configurable compression model**: move `COMPRESSION_MODEL` constant into dev-config file.
