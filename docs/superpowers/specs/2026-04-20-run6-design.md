# Run 6 — Design Spec
# First-Run Setup · Home Dir · Path Jail · safe_bash · Research Dispatch

**Date:** 2026-04-20
**Status:** Approved

---

## Goal

Give the agent a home directory, the ability to understand the user's working style (first-run interview), path-jailed file ops, fenced bash execution, and the ability to dispatch background research workers — all surfaced as Pi tools the agent calls itself.

---

## Guiding Philosophy

Keep strict code only where safety demands it. Everything else is loose: agent reads files, runs bash, extends itself via skills. No heavy class hierarchies for things the agent will do via files/scripts anyway.

**Strict (enforced in code):** PathJail, safe_bash blocklist/timeout/audit, HomeService bootstrap.  
**Loose (functions, not classes):** loadSkills(), buildSystemContext(), research worker creation.

## 2. Home Directory

### Structure

```
~/.research-assistant/
  config.md            ← first-run marker; written by agent after interview
  skills/              ← app-specific global skills
  workspace/
    <projectId>/       ← safe_bash CWD, path jail zone
  projects/
    <slug>/
      AGENTS.md        ← per-project context; written by agent on first open
  audit.log            ← appended on every safe_bash call
~/.agents/
  skills/              ← industry-standard compat; also loaded
```

### HomeService (injectable)

```ts
class HomeService {
  ensureDirectories(): Promise<void>   // mkdir -p all dirs above
  isFirstRun(): Promise<boolean>       // config.md missing = first run
  getHomePath(): string                // ~/.research-assistant abs path
}
```

Registered as singleton in `bootstrap()`. `AGENT_HOME_PATH` DI token = `~/.research-assistant` abs path.

`bootstrap()` calls `homeService.ensureDirectories()` before anything else.

## 3. System Context Assembly

Two pure async functions in `src/main/agent/context.ts`:

### loadSkills(projectFolderPath?: string): Promise<string>

Reads from 4 dirs (priority order — later wins on name collision):
1. `~/.agents/skills/`
2. `~/.research-assistant/skills/`
3. `<projectFolderPath>/.agents/skills/`
4. `<projectFolderPath>/.research-assistant/skills/`

Dirs 3 & 4 skipped if no `folderPath`. Each skill = directory containing `SKILL.md`. Parses frontmatter `name` + `description`. Returns:

```xml
<available_skills>
  <skill>
    <name>pdf-processing</name>
    <description>Extract PDF text, fill forms, merge files. Use when handling PDFs.</description>
    <location>/abs/path/to/pdf-processing/SKILL.md</location>
  </skill>
</available_skills>
```

Agent uses `read_file` to load full skill body when needed. No eager loading.

### buildSystemContext(projectId: string, folderPath?: string): Promise<string>

Assembles:
1. Contents of `~/.research-assistant/config.md` (if exists)
2. Output of `loadSkills(folderPath)`
3. Contents of `~/.research-assistant/projects/<slug>/AGENTS.md` (if exists)

Returns assembled string. Prepended to `systemPrompt` in `AgentSession`.

Slug = project name lowercased, spaces → hyphens.

## 4. PathJail

`src/main/agent/path-jail.ts` — pure security class, no DI needed (instantiated per session):

```ts
class PathJail {
  constructor(projectId: string, folderPath: string | null) {}
  validate(inputPath: string): string  // resolves to abs path or throws
}
```

Allowed read/write zones:
- `~/.research-assistant/workspace/<projectId>/`
- `<folderPath>/` if set

Read-only zone (for skill loading):
- `~/.research-assistant/skills/`
- `~/.agents/skills/`

Throws descriptive string returned to agent on violation. Does not log violations (not a security audit mechanism, just a guardrail).

## 5. Pi Tool Extensions on AgentSession

Registered in `AgentSession` constructor. Replaces the blanket `beforeToolCall: () => block: true`.

`beforeToolCall` is retained as a guard: logs every tool call, blocks any tool name not in the registered set.

### read_file({ path: string })
Path-jailed read. Returns file content string.

### write_file({ path: string, content: string })
Path-jailed write. Creates intermediate dirs if needed.

### list_dir({ path: string })
Path-jailed directory listing. Returns `string[]` of filenames.

### safe_bash({ command: string, intent: string })

Agent states intent before execution. Enforcement (in code, not by LLM):

- **CWD** locked to `~/.research-assistant/workspace/<projectId>/`
- **Blocklist** (pre-execution check, exact string match + regex): `rm -rf`, `sudo`, `chmod +x`, `mkfs`, `dd`, `curl`, `wget`, `eval`, backtick subshells `` ` ``, `$(...)`, absolute paths outside workspace
- **Timeout** 30s via `AbortController`
- **Output cap** 2KB; excess truncated with `"[truncated — <N> chars omitted]"` appended
- **Audit log** append: `{ ts, projectId, intent, command, exitCode }` → `~/.research-assistant/audit.log`

Returns `{ stdout, stderr, exitCode, truncated: boolean }`.

> **Note:** `safe_bash` may evolve into a generic `code_run` with language support in a future run. Deferred pending research into how major AI companies handle this.

### start_research({ query: string })

Spawns a background Pi `Agent` (see Section 6). Returns `{ taskId: string }` immediately. Non-blocking.

## 6. First-Run Flow

On `AgentSession` construction:
1. Call `homeService.isFirstRun()`
2. If true → prepend to `systemPrompt`:

```
You are setting up for first use. Ask the user these questions one at a time.
Do not ask all at once.
1. How do you organise your projects? (e.g. folder per project, by topic, other)
2. Do you use a note-taking app or work with plain folders?
3. What file types do you mainly work with?
4. Any naming conventions or folder structures you always follow?
After receiving all answers, write a concise summary to ~/.research-assistant/config.md
(plain Markdown, human-editable). Then confirm setup is complete.
```

3. Normal `systemPrompt` on subsequent sessions (config.md present).

## 7. Project Discovery

Triggered when agent first opens a project that has a `folderPath` set. Agent uses `list_dir` + `read_file` tools to walk the folder, then writes `~/.research-assistant/projects/<slug>/AGENTS.md` describing structure, conventions, key files.

No code orchestrates this — the agent decides to do it based on the `buildSystemContext` output (AGENTS.md missing = not yet discovered). A built-in global skill `discover_project.md` guides the agent on when and how.

"Rediscover project" = user asks agent to redo discovery; agent overwrites AGENTS.md.

## 8. ResearchService + Background Worker

`ResearchService.startResearch(projectId: string, query: string, folderPath?: string): Promise<{ taskId: string }>`

Called by the `start_research` Pi tool. Steps:

1. Generate `taskId` (uuid)
2. Build worker system prompt: researcher role + `buildSystemContext(projectId, folderPath)`
3. Create background Pi `Agent` with worker system prompt + same Pi tool set (read/write/list/safe_bash; no `start_research` — no recursive dispatch)
4. Fire `research:started` on EventBus
5. Subscribe to worker events:
   - `text_delta` → fire `research:progress` on EventBus (message = last chunk)
   - `agent_end` → save output as artifact via `ArtifactService`, fire `research:complete`
   - Error → fire `research:failed`
6. Call `worker.prompt(query)` — not awaited
7. Return `{ taskId }` immediately

### Research-complete callback to main agent

When `research:complete` fires for project P:
1. IPC sends `RESEARCH_COMPLETE` to renderer (ResearchStatusBar updates)
2. If `AgentSession` for project P exists and `!isStreaming`: inject synthetic prompt — `"Background research complete (task ${taskId}). Query: '${query}'. Artifact: ${filePath}. Briefly summarise findings for the user."` — then call `session.injectAndPrompt()`
3. If `isStreaming`: queue inject, fire when current stream ends

`AgentSession` gains:
- `isStreaming: boolean` flag (set true on `message_update`, false on `agent_end`)
- `injectAndPrompt(content: string): Promise<void>` — adds message + calls `agent.prompt()`

## 9. UI Changes

### LeftSidebar — create project dialog
- Add optional "Browse…" button → `OPEN_FOLDER_DIALOG` IPC → `dialog.showOpenDialog({ properties: ['openDirectory'] })` → sets `folderPath` in create payload
- `CREATE_PROJECT` payload: `{ name: string, folderPath?: string }`

### Project context menu
- "Link folder" / "Change folder" → folder picker → `LINK_FOLDER` IPC
- "Reveal in Finder" → `shell.openPath(folderPath)` (Electron built-in)

### ResearchStatusBar
- Listens `RESEARCH_STATUS_UPDATE` → spinner + last progress message
- Listens `RESEARCH_COMPLETE` → "Done: [query]" for 3s then clears
